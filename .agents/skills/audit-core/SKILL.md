# ModWorld — Audit & Repair Contract

**Purpose:** Find and repair reproducible mismatches between canonical data, engine, runtime, persistence, UI, tests/gates, and player-facing wiki. A completed audit produces **verified fixes or explicit blockers**, not a findings-only document.

This file is an **audit work order**, not a substitute for `AGENTS.md`. Use `AGENTS.md` for document roles, scope, ownership, commands and verification; reuse it if already loaded. The **current working tree** takes precedence over names, paths, line numbers, gate counts, and historical observations recorded below. Consult only the relevant document sections listed there. Apply its documentation update policy; an audit does not authorize incidental rewrites or todo maintenance.

## 1. Boundaries and definitions

- **Preserve in-flight work.** Never reset, checkout, stash, clean, commit, rewrite history, or overwrite another workstream's edits. Edit only files needed for a verified fix; avoid incidental formatting, reorderings, or refactors. Do not start competing servers or touch unrelated artifacts.
- **Honor ownership.** Numerical gameplay values belong in `tools/data/*.json`; `engine/` and `game/src/` consume rather than duplicate balance values. `docs/wiki/*.html` is generated from `game/src/wiki/pages.ts`: rebuild using `npm run wiki`, never hand-edit. Do not rebalance, add content, or redesign without a demonstrated rule violation and authority.
- **Approval:** Follow `AGENTS.md`. Requested design changes need no repeated approval; ask about new dependencies, unclear scope or unsafe/lossy compatibility changes. An audit alone does not authorize a redesign.
- **Statuses:** `confirmed` = reproducibly violates a named rule; `fixed` = regression shown failing before and passing after; `blocked` = specific missing owner decision prevents repair; `unconfirmed` = insufficient reproduction, **no speculative code change**; `out-of-scope` = real issue assigned to another workstream. Intended behavior is not a defect.
- **Priority:** Correctness and preservation > reproducing the player's behavior > regression coverage > wall-clock efficiency > tool-call/token reduction. No arbitrary call/turn limit or repeated approval gate.

## 2. Execution protocol

### 2.1 Define the audit boundary

There are two supported modes:

| Mode                | When                                | Required coverage                                                                                                                                                                                                  |
| ------------------- | ----------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Full audit**      | Explicit end-to-end game audit      | Trace each applicable core flow in §4 and evaluate all A–Q contracts in §3. Record **tested / read-only / not exercised** and why. Full baseline; rerun checks invalidated by fixes.                                            |
| **Targeted repair** | Specific defect, contract or domain | Trace the implicated flow and connected contracts only. Run focused baseline checks first, then affected tests/gates; expand to full verification for shared behavior and before declaring cross-layer completion. |

Do **not** turn every checklist item, file, or historical lead into a fresh task when it does not affect the active scope. Conversely, do not label a component audited because a test suite is green without tracing its consumers.

### 2.2 One-pass baseline

1. Inspect relevant local files and current key symbols before editing. Work inside the active sandbox under `AGENTS.md`; do not inspect Git state, compare with commits or use another worktree. Preserve existing local edits.
2. **Full audit:** run `npm run verify`, `npm test` and `npm run check` once before the first fix; record exit statuses, current counts and existing FAIL/watch lines. `check` includes root typecheck and Svelte checking, so do not run a duplicate typecheck. **Targeted repair:** run only relevant checks initially; broaden when the touched contract requires it.
3. Reuse the baseline until changed code invalidates it. Never relabel a pre-existing failure as a new regression. If a command is unavailable or failing, report that exact condition instead of assuming a pass.
4. Where a visual or interactive flow is involved, use the integrated headless Playwright browser at `http://localhost:5173` with the existing server only; verify at **1920 × 1080**. State the host exercised: `/`, `wiki.html#<page>`, or `/__showcase#<id>` (prefer the showcase for UI).

Commands: `npm run verify` (current registry in `tools/lib/writers.ts:CAGES`), `npm test`, `npm run typecheck` (root engine/tools), `npm run check` (root + Svelte), `npm run wiki` (generated docs); domain-specific: `npm run map:check`, `npm run map`, `npm run skills`, `npm run gallery`. Isolated cage entry points: `node tools/check.ts --checks|--sync`, `node tools/loot.ts --checks|--bias`, `node tools/bases.ts --checks|--write`, `node tools/skills.ts --checks`, `node tools/imprint.ts --checks`, `node tools/map.ts --checks`. Verify actual scripts before executing; `--sync` and `--write` **change files** and are not inspection commands.

### 2.3 Investigate → prove → repair → verify

For each candidate finding:

1. **Rule:** state the invariant, its owner (`tools/data/`, `engine/`, gate or save contract), and actual reader(s). Prefer targeted searches; read only implicated files/sections, expanding as evidence requires. Reuse verified context; do not repeatedly read unchanged sources.
2. **Reproduce:** isolate a fixed seed, minimal fixture, or named browser flow. For cross-layer problems, observe the complete chain. If no reproducible violation is established, mark `unconfirmed` or a documented `blocked` decision—do not patch a guess.
3. **Classify:** implementation error, stale reader/UI/prose/save, contract/gate gap, or intended behavior.
4. **Fix at the owner:** repair the canonical source and impacted consumers together. Avoid UI-only compensations and duplicating formulas. Make coherent edits; do not include unrelated cleanup.
5. **Regression:** demonstrate a relevant test/probe **fails before → passes after**. Test externally observable behavior, including negative and adjacent states; use the existing owner test file before making a new one. Where a pre-fix run is impractical, explain and use an isolated mutation or controlled fixture as evidence—never claim an unobserved red phase.
6. **Verify:** focused tests and gates first, then broader checks warranted by the blast radius; broader checks when changes invalidate the full baseline. Do not rerun an unchanged passing suite reflexively. Rebuild wiki if data, engine, wiki source, or player-facing rules change; check human-written wiki sentences separately.
7. **Record:** report rule, reproduction, root cause, change, proof, affected files and status in the response or an explicitly requested report. Do not append routine run records to this skill. Preserve prior work; restore temporary mutations exactly. Stop revisiting a closed finding absent new evidence.

**Progress control:** If an approach fails repeatedly without new evidence, reassess the hypothesis. Parallel work is allowed only on independent concerns with distinct file ownership. Do not spawn a subagent for a trivial lookup. Surface genuinely blocking questions immediately; keep routine narration short.

## 3. Contract registry — audit the relationships, not only features

Each letter is a **contract category**, not an instruction to run a full repository sweep on every finding. Check the entries affecting the mode/scope (§2.1), then mark each as **exercised, read-only, or not applicable** in the report. Use current implementations rather than assuming recorded symbols have not moved.

### F–J · State, presentation and time

- **F — Online/offline/save parity:** Reproduce the same seeded elapsed span with live tick, `catchUp`/`catchUpAsync`, and save → load → continue. Compare resulting states. Old saves migrate without loss; unknown schemas reject safely.
- **G — UI/wiki truth:** Sheet reads the combat value, not a newly calculated approximation; rounding affects display only. Caps and refusal reasons reflect the actual rule. Compare player-facing statements in `game/src/wiki/pages.ts`; a generated wiki rebuild does not correct hard-coded prose.
- **H — HUD (only when touched):** Shared `HudLayout` in `game/src/ui/hud/hud-layout.ts` (`HudRegionId`, `HUD_REGION_META`, `DEFAULT_HUD_LAYOUT`) must agree with `HudLayoutEditor.svelte` and `App.svelte`. Studio Apply previews, game Apply saves; old layouts backfill defaults. Exercise the live region at 1920 × 1080; follow `variables.css` sizing and `AGENTS.md` UI rules.
- **I — RNG discipline:** No gameplay-path `Math.random` in `engine/`/`game/src/`; cosmetic exceptions must be identified. Golden sequence: fixed seed + N ticks produces the same roll order unless intentionally changed.
- **J — Clock, replay and exploits:** Compare scheduler / catch-up / reload for backward/forward system time, DST/timezone, hidden→visible, long sleep, boss/dungeon payout, snapshot restore and reload mid-tick. No duplicate rewards or circumvented cost. Reproduce relevant exploit surfaces: aura reservation via toggle/respec/preset, HP-cost at 1 HP, filter spam, escrow enter/leave, travel rounding, full-bag sale, salvage/re-craft. A manual observation becomes a confirmed issue only with repeatable evidence and a recorded test.

### K–Q · Robustness and audit quality

- **K — Numeric hygiene:** Internal decisions compare raw values; formatters (`r1`, `r2`, `fmt`, `sheetFixture.ts`) only round for presentation. For impacted formulas test zero divisors, `NaN`/`Infinity`/negative zero, off-by-one cap edges, threshold equality, high-level overflow and accumulation drift. Soak checks require a stated numeric expectation, not a speculative performance claim.
- **L — Storage/multi-tab:** Inspect `save.ts` IndexedDB/localStorage mirror, three slots, import/export, snapshots, `SCHEMA_VERSION`, and `accountWriterLock.ts` (`modworld:account-writer`) when impacted. Test unavailable/quota-limited/corrupt storage; two tabs on one slot (B read-only until takeover); missing Web Locks must disable writes. Probe map editor/snapshot/restore paths for uncovered writes. Confirm snapshot bounds, export/import fidelity, `http` and `file://` wiki/game needs, and suspended tab behavior when within scope.
- **M — Economy conservation:** For affected economy and town transactions contracts, test gold/junk/stones/craft currency across buy→craft→sell, salvage→re-craft and dungeon escrow; measure by relevant level band/period only when the rule defines an expected identity.
- **N — Long-session performance:** Only benchmark a credible performance finding after measuring baseline: ticks at level Cap with full bag/stash/toggles, `catchUpPlan`/`schedulerBatch`/`MAX_BATCH`, large saves/snapshots, UI list/repaint listener growth (`game/src/wiki/main.ts`). Use `soak.test.ts` where suitable. Without a falsifiable threshold or comparative baseline, record as an observation—not a confirmed defect.
- **O — Gates must bite:** For a gate used to prove a **new/modified** finding, use a temporary local copy inside the active sandbox; assert red, then restore and assert green. Reject self-comparing/stale gates and sync-anchor duplication. Never mutate another workstream's in-flight files or run broad mutation sweeps without scope.
- **P — Intent/document drift:** Trace relevant formulas and behavior through data notes and player-facing `pages.ts` claims to actual readers. Missing a gate alone is not a defect; unrequested behavior changes are. Requested design changes supersede older intent. Update only affected documentation under the policy in `AGENTS.md`.
- **Q — Deterministic negative-path tests:** Fixed seeds, clock mocks, no network/file-order dependence. Test refusals that a fix touches (filter, unequippable/ Broken gear, bag full, aura over-reservation, dungeon Push forfeiture). Put new cases in the existing owner test, or `audit-follow.test.ts` / `audit-regressions.test.ts` if no better home exists. A local unit test cannot clear an untested cross-layer flow.
- **R — Roster coverage against the life-skill tables (settled 2026-10-15):** every Species now reads against a life skill. `potion_source` is true on the six tribal lines (Goblin · Orc · Kobold · Human · Lizardman · Elf) and on no brute humanoid, so Race still grants nothing (X49). `fieldwork.hunt` feeds 27 of 35 Species — `edible_species` (14) plus 11 `food_drops` rows — and the eight that stay unfed are inedible by ruling (`orc · skeleton · mummy · vampire · demon · golem · wraith · imp`). `hunt.material_drops` pays the same keys the sites pay (`ore · timber · rarewood`) to 6 Species, and `actions.mine.mob_resource` / `grove.mob_resource` name the provenance: the hex owns the rate, the Skill XP and the Mastery, the kill is only the chance you meet. `lean` was retagged where the body disagreed (`mist · wisp` herb → junk) and 65 junk items were renamed off the `<Species> Mote/Scrap/Relic/Sigil/Shard` template onto held objects. The remaining locks are settled: LT14 proves identity, conservation and raising each configured lean; BS13 accepts any nonempty set of unique supported Shield profiles while checking weight and Mod validity; X25 requires a positive ES recharge delay and player-only ES. The six Variant names and their junk items were updated together. Nothing in this bullet is open twice.

## 4. End-to-end player flows (full audit; targeted repairs select applicable flows)

For each exercised flow, name the functions traversed and create a deterministic observable probe. A passing isolated unit test alone does **not** clear the flow.

1. **Character/equipment:** Mods → `buildCharacter` → combat read → character sheet. Bag/stash/escrow must not contribute equipped stats. Exercise equip, replacement, removal, break/repair, restore, pool clamps; cover Max HP/Mana/ES, regen, resistance, Evasion, Accuracy, attack speed, weight, capacity, caps.
2. **Drops and item decisions:** `rollDrop` → Collector → filter → capacity → `autoEquip` → displaced item → overflow. Test both ring cells and empty slot, real low-band rolls, locked/Broken gear, `equipMargin`, full bag, escrow and offline drops, reserved gear. Readout/filter/auto-equip use the same score and true refusal.
3. **Skill ownership/reservation:** First copy vs duplicate, drops, XP/levels, skill slot, cooldown, activation, recast, expiry, disable, save/import. Unknown/unowned skills must never self-activate, reserve, apply, recast, or appear in the HUD; respec/preset cannot evade reservation limits.
4. **Combat/recovery:** Perfect dodge → Evasion → block → Armour → resistance → damage taken → ES → HP. Test overflow, partial ES, status timing/DoT caps, stun/shock, recharge delay, regen, Hunger, healing/leech, Push and Camp. Sheet must reflect tick calculations.
5. **Progression/persistence:** Levels, allocation, tree, Mastery, respec, presets, crafting, farming/fieldwork, food/potions, dungeon↔combat, migrations and offline parity (§3F).
6. **Player-facing contract:** UI labels/reasons and wiki prose match the same engine/data rule; rebuild generated wiki when needed (§3G).

## 6. Completion and reporting

**Full audit finishes only when:**

- All **confirmed in-scope** defects are `fixed` with reproducible regression proof or `blocked` with an exact owner decision. No issue ends as merely "noted". `unconfirmed` and `out-of-scope` are disclosed, not silently marked complete.
- Every contract that a fix touches has a relevant observable probe; each newly relied-on/changed cage can be shown to reject a deliberately broken invariant (§3O). Record live-key/gate coverage for affected values.
- Record actual baseline results and rerun checks invalidated by the changes. Reuse unchanged passing checks under `AGENTS.md`; never claim an unrun suite passed. For targeted changes, record scoped checks and justified omissions.
- `npm run wiki` is rebuilt when required, including correction of manual rule prose. Temporary mutations/diagnostics are cleaned up without reverting unrelated edits; the working tree is preserved. No unauthorized commit or scope creep.

**Final report:** start with outcomes and counts; then for every finding provide `symptom → invariant/source → reproducible cause → owned fix → affected files → before/after probe`. Include gate/test/typecheck counts and pre-existing failures, owner decisions, unconfirmed/out-of-scope leads, actual browser host if relevant, and contract/flow coverage. Report **what was traced and verified**, not an unsupported claim that the whole game was audited.

**Non-goals:** speculative balance/content tuning; redesigns; schema changes needing approval; cosmetic refactors; changes to another workstream's files; lengthy transcripts or additional report files without a user request.
