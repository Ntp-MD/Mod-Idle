# แผน QoL: ช่วยให้ผู้เล่นเลือกสิ่งที่จะทำต่อ

สถานะ: แผนงานสำหรับพัฒนา

## เป้าหมายและขอบเขต

ลดภาระการจำข้อมูล การสลับหน้าจอ และงานจัดการซ้ำ ให้ผู้เล่นเห็นเป้าหมายที่เลือกไว้และลงมือทำต่อได้ โดยยังเลือกแนวเล่นและ build เอง

ใช้หมายเลขจากรายการ QoL ที่ผู้ใช้เลือก เก็บเฉพาะเจ็ดงานนี้:

| หมายเลขเดิม | งาน | ผลลัพธ์ที่ต้องได้ |
| --- | --- | --- |
| 1 | เป้าหมายถัดไปใน Journey | เห็นหนึ่งเป้าหมาย เหตุผล และปุ่มทำต่อ |
| 3 | เชื่อมสิ่งที่ขาดไปยังวิธีหา | เปิดแหล่งหา ปักหมุด และติดตามจำนวนจากสิ่งที่ขาด |
| 4 | อธิบายปุ่มที่กดไม่ได้ | เห็นสาเหตุและวิธีแก้โดยไม่ต้องเดา |
| 5 | อธิบายกิจกรรมทางเลือก | เข้าใจว่าแต่ละระบบมีประโยชน์เมื่อไร |
| 6 | ตั้งค่าจัดการของใน flow เดียว | ตั้ง Auto Equip ตัวกรองของ และ Auto-Return พร้อมเห็นผลที่จะเกิด |
| 7 | จัดความสำคัญของการแจ้งเตือน | เรื่องที่ต้องตัดสินใจเด่น และเหตุการณ์ซ้ำถูกรวม |
| 8 | ตัวช่วยอ่าน passive tree | หา node ที่เกี่ยวข้องกับเป้าหมาย พร้อมดูเส้นทางและราคาจริง |

## ฐานที่มีอยู่แล้ว

- [App.svelte](../../game/src/App.svelte) ประกอบ Journey, เมนู, การติดตาม Delivery, การแจ้งเตือน และ settings
- [TravelCard.svelte](../../game/src/ui/TravelCard.svelte) มี primary action และแสดง `primary.reason` อยู่แล้ว
- [MapJourney.svelte](../../game/src/ui/MapJourney.svelte) มี Patrol และ Auto-Return
- [Forge.svelte](../../game/src/ui/Forge.svelte), [CraftWorkshop.svelte](../../game/src/ui/CraftWorkshop.svelte) และ [material-sources.ts](../../game/src/sim/material-sources.ts) เป็นจุดเริ่มของงานวัตถุดิบและแหล่งหา
- [gear.ts](../../game/src/sim/gear.ts), [filter.ts](../../game/src/sim/filter.ts) และ [exploration.ts](../../game/src/sim/exploration.ts) เป็นเจ้าของพฤติกรรมจัดการของและเดินทางอัตโนมัติ
- [ObjectiveFeed.svelte](../../game/src/ui/ObjectiveFeed.svelte), [DeliveryNotice.svelte](../../game/src/ui/DeliveryNotice.svelte) และ [LogBox.svelte](../../game/src/ui/LogBox.svelte) แสดงเป้าหมาย โอกาสส่งของ และประวัติเหตุการณ์
- [PassiveTreeBoard.svelte](../../game/src/ui/PassiveTreeBoard.svelte) มีการเลือก node ดูเส้นทางและซื้อ path แล้ว

เริ่มจากต่อยอดองค์ประกอบเหล่านี้ ตรวจความสามารถปัจจุบันก่อนเพิ่ม helper หรือ component ใหม่

## หลักการร่วม

- ใช้ Journey และ HUD regions เดิม ข้อมูลเป้าหมายกับการแจ้งเตือนต้องไม่ถูกแสดงซ้ำหลายแห่ง
- เป้าหมายที่ผู้เล่นเลือกเองมีลำดับสูงกว่าคำแนะนำอัตโนมัติ
- ปุ่มนำทางใช้เป้าหมายเดียวกันได้จาก Journey สูตรผลิต เหตุผลที่ติดขัด และรายการแจ้งเตือน
- อ่านราคา จำนวนของ เงื่อนไข และผลการอนุญาตจากเจ้าของข้อมูลหรือ validator เดิม การแสดงผลต้องไม่สร้างสูตรคู่ขนาน
- การเลือกแหล่งหาและปักหมุดเป็นการนำทาง ผู้เล่นสั่งเดินทาง ซื้อของ หรือใช้ทรัพยากรผ่าน action เดิม
- คำนวณข้อความและ preview แบบอ่านอย่างเดียว การเปิดหน้าจอไม่เปลี่ยน RNG เวลา เงิน ของ หรือสถานะสัญญา
- คง native semantics, keyboard access และ visible focus เหตุผลสำคัญต้องอ่านได้โดยไม่พึ่ง hover
- เก็บเฉพาะ reference ที่จำเป็น เช่น recipe ID, contract ID หรือ node ID แล้วอ่านจำนวนและราคาใหม่จาก state ปัจจุบัน
- เป้าหมายที่ผูกกับตัวละครต้องแยกตามตัวละคร ส่วน preference การแสดงผลใช้ settings เดิม ถ้าต้องเพิ่มข้อมูลที่บันทึก ให้ backfill save เก่าด้วยค่าเริ่มต้นและรักษาความหมายของข้อมูลเดิม

## 1. เป้าหมายถัดไปใน Journey

### งานที่จะทำ

- เพิ่มส่วนแสดงเป้าหมายหลักหนึ่งรายการใน Journey พร้อมเหตุผล ความคืบหน้าที่เกี่ยวข้อง และปุ่มทำต่อ
- รองรับเป้าหมายจากสิ่งที่มีอยู่ในเกม: สูตรที่ติดตาม, Delivery ที่ติดตาม, จุดหมายที่เลือก และเป้าหมาย passive ที่ผู้เล่นเลือก
- ใช้ reference ของงานเดิมร่วมกับข้อ 3 และ 8 แทนการสร้างสำเนา quest หรือรางวัล
- เมื่อไม่มีเป้าหมายที่ผู้เล่นปักไว้ ให้เลือกคำแนะนำจากงานที่ทำได้จริงใน state ปัจจุบัน โดยใช้ลำดับคงที่และอธิบายเหตุผลได้
- รักษาคำแนะนำเดิมขณะที่ยังเกี่ยวข้อง เพื่อให้ผู้เล่นอ่านทันและไม่สลับเป้าหมายตามทุก tick
- ให้เปลี่ยนเป้าหมาย ปิดคำแนะนำ และกลับมาเปิดได้ เป้าหมายที่เสร็จ หมดอายุ หรืออ้างถึงสิ่งที่ไม่มีแล้วต้องมีสถานะที่เข้าใจได้

### เกณฑ์ตรวจรับ

- เป้าหมายที่เลือกเองไม่ถูกคำแนะนำอื่นแย่งตำแหน่ง
- ปุ่มพาไปยังสูตร สัญญา จุดหมาย หรือ node ที่ตรงกับเป้าหมาย พร้อมคง context ของรายการนั้น
- จำนวนของและความคืบหน้าอัปเดตจาก state จริง โดยเป้าหมายไม่กระพริบเปลี่ยนระหว่างการอ่าน
- reference ที่หมดอายุหรือหาไม่พบไม่ทำให้หน้าจอพัง และไม่พาไปยังรายการอื่นโดยเงียบ ๆ

## 3. เชื่อมสิ่งที่ขาดไปยังวิธีหา

### งานที่จะทำ

- เปิดรายละเอียดแหล่งหาจากวัตถุดิบที่ขาดใน Forge และ Craft รวมถึงของใน Delivery ที่ผู้เล่นติดตาม
- แสดงจำนวนที่มี จำนวนที่ต้องใช้ และส่วนที่ยังขาดจาก inventory และกฎการใช้ของเดิม
- ใช้รายการแหล่งหาที่มีอยู่ ให้เลือกแหล่งและปักหมุดบน map ได้โดยตรง
- ให้ติดตามสิ่งที่ขาดเป็นเป้าหมายใน Journey แล้วกลับไปเปิดรายการต้นทางได้
- เคารพสถานะการสำรวจ แหล่งที่ยังไม่รู้จักแสดงเงื่อนไขหรือข้อมูลที่ผู้เล่นรู้ได้จริง
- เมื่อมีหลายแหล่ง ให้แสดงข้อมูลสำหรับเลือก เช่น ชนิดกิจกรรมและการเข้าถึง โดยไม่กล่าวอ้างเวลาเฉลี่ยหรือความคุ้มค่าที่ระบบยังไม่ได้คำนวณ

### เกณฑ์ตรวจรับ

- เริ่มจากของที่ขาดแล้วปักหมุดแหล่งหาได้ โดยไม่ต้องจำชื่อและค้นในอีกหน้าด้วยตัวเอง
- สลับตัวละคร รับของ ใช้ของ หรือเปลี่ยนสูตรแล้วจำนวนที่แสดงยังถูกต้อง
- การปักหมุดไม่เริ่มเดินทางหรือใช้ทรัพยากรเอง และย้อนกลับไปดูสูตรหรือสัญญาเดิมได้
- กรณีไม่รู้แหล่งหา แหล่งยังเข้าไม่ได้ หรือรายการหายไปมีข้อความอธิบายที่เหมาะสม

## 4. อธิบายปุ่มที่กดไม่ได้

### งานที่จะทำ

- ใช้การแสดง `primary.reason` ของ TravelCard เป็นฐาน ขยายความสม่ำเสมอไปยัง Forge, Craft, การซื้อขาย และ passive tree
- อ่านสาเหตุจาก validator เดียวกับ action ที่จะทำจริง
- แสดงสาเหตุหลักใกล้ action และเปิดดูเงื่อนไขเพิ่มเติมได้เมื่อจำเป็น
- เชื่อมเหตุผลไปยังวิธีแก้ที่มีอยู่ เช่น ดูวัตถุดิบที่ขาด เปิดเมืองที่เกี่ยวข้อง หรือดูเส้นทางไปยัง node
- แยกเหตุผลที่ผู้เล่นแก้ได้จากข้อจำกัด เช่น read-only, กำลังเดินทาง หรือกำลังต่อสู้

### เกณฑ์ตรวจรับ

- เหตุผลตรงกับผล refusal ของ action และอัปเดตเมื่อ state เปลี่ยน
- อ่านเหตุผลได้ด้วย keyboard และไม่ต้อง hover ปุ่ม disabled
- ปุ่มวิธีแก้เปิด context ที่ถูกต้อง กรณีแก้จากหน้าจอนี้ไม่ได้ต้องบอกสิ่งที่ต้องทำให้ชัด
- ปุ่มกดได้ยังใช้ action และการตรวจสิทธิ์เดิม ป้องกัน state เปลี่ยนหลังการแสดงผลได้ตามเดิม

## 5. อธิบายกิจกรรมทางเลือก

### งานที่จะทำ

- เพิ่มคำอธิบายสั้นในจุดเข้าใช้ Farm, Craft, Delivery และ Market ว่าเหมาะใช้เมื่อใดและช่วยเรื่องอะไร
- เชื่อมคำอธิบายกับเป้าหมายที่ผู้เล่นกำลังติดตามเมื่อมีความเกี่ยวข้อง
- ทำให้วงจรล่า รับของ ปรับตัวละคร และเดินหน้าต่ออ่านเข้าใจได้จากหน้าหลัก
- ใช้ข้อความแนะนำและระดับความเด่นให้เหมาะกับความจำเป็นจริงของกิจกรรม

### เกณฑ์ตรวจรับ

- ผู้เล่นอธิบายประโยชน์ของแต่ละกิจกรรมได้จากข้อความสั้นตรงจุดเข้าใช้
- การแจ้งเตือนกิจกรรมทางเลือกไม่ใช้ระดับเดียวกับปัญหาที่ทำให้เล่นต่อหรือบันทึกไม่ได้
- การเปลี่ยนข้อความไม่เปลี่ยน unlock เงื่อนไขรางวัล เศรษฐกิจ หรือความสามารถในการเข้าถึงระบบ

## 6. ตั้งค่าจัดการของใน flow เดียว

### งานที่จะทำ

- รวมทางเข้าของ Auto Equip, ตัวกรองของ และ Auto-Return ให้ปรับค่าที่เกี่ยวข้องได้ใน flow เดียว
- อ่านและเขียนผ่าน settings และ state owners เดิม ให้หน้าตั้งค่าอื่นแสดงค่าเดียวกัน
- แสดงตัวอย่างผลกับกระเป๋าปัจจุบัน: ของที่จะใช้แทน ของที่จะเก็บ ของที่จะถูกจัดการตามกฎ และเงื่อนไขกลับเมือง
- ใช้การตัดสินใจเดียวกับ Auto Equip และ filter จริงในการสร้าง preview
- แสดงการป้องกันของที่ล็อกและของที่มี `heldFor` ตามกฎเดิม
- แยกการบันทึกค่าจากคำสั่งจัดการของทันทีให้ผู้เล่นเข้าใจผลของการกดปุ่ม
- อธิบายสถานะที่ระบบทำงานต่อไม่ได้ เช่นไม่มีพื้นที่เก็บของ พร้อมทางไปแก้ไข

### เกณฑ์ตรวจรับ

- Preview ไม่แก้ live state หรือกิน RNG และผลที่ยืนยันใช้กฎเดียวกับ preview
- ของที่ได้รับการป้องกันตามกฎเดิมยังปลอดภัยทั้งจาก preview การจัดการของด้วยมือ และระบบอัตโนมัติ
- เปิดปิด Auto-Return ระหว่างสถานะต่าง ๆ แล้วคงพฤติกรรมเดินทางและกลับไปทำ Patrol ตามกฎเดิม
- เปลี่ยนค่าจากทางเข้าใดก็เห็นค่าเดียวกัน โหลดกลับมาได้ และรองรับค่าเริ่มต้นของ save/settings เก่า
- บัญชี read-only ไม่สามารถสั่ง action ที่แก้สถานะตัวละครได้

## 7. จัดความสำคัญของการแจ้งเตือน

### งานที่จะทำ

- ใช้ Journey แสดงเรื่องที่พร้อมทำหรือจำเป็นต้องตัดสินใจ โดยเชื่อมกับเป้าหมายหลักในข้อ 1
- จัดลำดับตามผลกระทบจริง เช่น ปัญหาการบันทึกหรือ writer lock, กิจกรรมที่หยุดรอการแก้ไข, งานที่ผู้เล่นติดตาม และโอกาสทางเลือก
- รวมเหตุการณ์ซ้ำเป็นรายการเดียวพร้อมจำนวนหรือรายละเอียดที่เปิดอ่านได้
- ลดการแจ้งซ้ำจากสถานะเดิมที่ยังไม่เปลี่ยน พร้อมให้ผู้เล่นรับทราบหรือซ่อนโอกาสทางเลือกได้
- คงรายละเอียดและประวัติที่จำเป็นใน feed โดยไม่แสดงคำเตือนเดียวกันซ้ำทั้ง toast, Journey และหน้ารายละเอียด
- เปิดรายละเอียดที่เกี่ยวข้องได้ตรงรายการ การรับทราบ notice ใช้ semantics ของเจ้าของเหตุการณ์เดิม

### เกณฑ์ตรวจรับ

- เหตุการณ์เดิมไม่สร้างแจ้งเตือนใหม่ทุก tick และการรวมรายการไม่ทำให้ข้อมูลธุรกรรมหรือประวัติสูญหาย
- เหตุสำคัญด้านการบันทึกและการหยุดทำงานยังมองเห็นได้
- การซ่อนหรือรับทราบ notice ไม่รับรางวัล ส่งของ เปลี่ยนอายุสัญญา หรือทำให้ offer ถูกสุ่มใหม่
- เปิดรายการแจ้งเตือนแล้วเข้าสู่รายละเอียดและ action ที่ตรงกัน

## 8. ตัวช่วยอ่าน passive tree

### งานที่จะทำ

- ให้เลือกเป้าหมาย เช่น เพิ่มความอยู่รอด จัดการมานา หรือเสริมสกิลที่ใช้อยู่
- แสดงตัวเลือกที่เกี่ยวข้องจาก grants และ effects ที่อ่านความหมายได้จริง พร้อมอธิบายว่าเกี่ยวข้องกับเป้าหมายอย่างไร
- ใช้สกิลและอุปกรณ์ปัจจุบันเป็น context เมื่อข้อมูลรองรับ และอธิบายเงื่อนไขของโบนัสเฉพาะอาวุธหรือสกิล
- ใช้ระบบ search, selection, route preview และ path purchase เดิมในการนำผู้เล่นไปยัง node
- แสดง Tree Points และ Attainment แยกกัน รวมราคาเส้นทาง เงื่อนไขการเชื่อม และ incompatibilities
- ให้ติดตาม node เป้าหมายใน Journey ได้ คำแนะนำไม่จัดสรรแต้มแทนผู้เล่น
- แสดงผลแลกเปลี่ยนของ Keystone ให้ชัด คำแนะนำต้องไม่รับรองว่าเป็น build ที่ดีที่สุดจากคะแนนรวมที่ไม่ได้รองรับสูตรจริง

### เกณฑ์ตรวจรับ

- ตัวเลือกมีเหตุผลที่ย้อนกลับไปตรวจ grants หรือ effects ได้ และสัมพันธ์กับเป้าหมายที่เลือก
- เส้นทางและราคาตรงกับระบบซื้อ path จริง รวมกรณีเงินไม่พอ คู่ Keystone ที่ใช้ร่วมกันไม่ได้ และเป้าหมายที่ยังไปไม่ถึง
- เปลี่ยนอาวุธ สกิล ranks หรือแต้มแล้วคำแนะนำและ preview อัปเดตตาม state
- ผู้เล่นยังค้นหา เลือก node และวางทางผสมเองได้ พร้อมยกเลิกคำแนะนำได้
- คงโครงข่าย ราคา โบนัส และทางเข้า Keystone ที่แยกเป็นอิสระจาก Normal roads ตามกฎปัจจุบัน

## ลำดับส่งมอบ

1. **ชุด A: ข้อ 1, 3, 4** — ทำเป้าหมาย Journey และการนำทางจากของที่ขาดหรือ action ที่ติดขัดให้ต่อกันครบหนึ่ง flow ก่อนขยายไปทุกหน้าที่เกี่ยวข้อง
2. **ชุด B: ข้อ 5, 7** — ปรับความชัดเจนของกิจกรรมและจัดลำดับการแจ้งเตือนร่วมกับ Journey
3. **ชุด C: ข้อ 6** — รวม flow การตั้งค่าจัดการของ พร้อม preview และตรวจการป้องกันของ
4. **ชุด D: ข้อ 8** — เพิ่มตัวช่วย passive tree โดยใช้การติดตามเป้าหมายและการนำทางที่ส่งมอบแล้ว

แต่ละชุดต้องทำและตรวจรับจบได้ด้วยตัวเอง คงงานที่ยังไม่ทำไว้ในแผน ไม่สร้าง UI ที่กดแล้วไม่มีผล

## การตรวจรับรวม

- ทดสอบ flow จริง: เลือกเป้าหมาย → เห็นสิ่งที่ขาด → ไปยังแหล่งหรือหน้าที่แก้ได้ → กลับมาทำงานเดิมต่อ
- ตรวจเป้าหมายหลายประเภท เหตุผลที่กดไม่ได้ state ที่เปลี่ยนระหว่างเปิดหน้า reference หมดอายุ และ read-only
- ใช้ focused tests สำหรับพฤติกรรมที่เปลี่ยน รวมการจัดการของ การติดตามงาน และการซื้อ path ของ tree
- เมื่อเพิ่มข้อมูลที่บันทึก ตรวจ default/backfill, save เก่า และ round-trip โดยรักษาของ เงิน แต้ม progress และความหมายของข้อมูลเดิม
- รัน typecheck, Svelte check ที่ไม่ยอมรับ warnings และ production build ตาม [AGENTS.md](../../AGENTS.md)
- ตรวจ UI ผ่าน dev server เดิมที่ port 5173 ใน integrated browser ที่ 1920 × 1080 ใช้หนึ่ง visible tab และปิดหลังตรวจ หากไม่มี browser ให้รายงานข้อจำกัดโดยตรง
- ตรวจ keyboard, focus, การอ่านเหตุผล และ scroll owner ของ Journey/feed รวมถึง HUD layout ที่ผู้เล่นบันทึกไว้
- อัปเดตเฉพาะข้อความอธิบายพฤติกรรมที่เปลี่ยน และสร้าง wiki ใหม่เมื่อแก้แหล่งข้อมูล wiki หรือพฤติกรรมที่ผู้เล่นต้องเข้าใจ

## เกณฑ์จบงาน

- เจ็ดรายการที่เลือกผ่านเกณฑ์ตรวจรับและเชื่อมกับเกมจริงครบ
- ผู้เล่นหาเป้าหมายที่เลือกไว้ เห็นเหตุผลของสิ่งที่ติดขัด และไปทำขั้นถัดไปได้จาก context ปัจจุบัน
- การเลือกกิจกรรมทางเลือกและ build ยังคงเป็นของผู้เล่น
- รายงานสิ่งที่ส่งมอบ ผลตรวจ และข้อจำกัดที่ยังยืนยันไม่ได้ตามจริง
