## Where a new file goes

| File kind | Location | Rule |
| --- | --- | --- |
| Guide, decision or reference | topic folder | Link it from this index. Do not create a second topic index. |
| Execution plan | `docs/plan/<topic>.html` | One plan per initiative. Keep the `plan-current` marker. |
| Player-facing game reference | `docs/reference/wiki/` | Generated by `tools/wiki.ts`; edit the source, not the HTML. |
| Art source or review candidate | topic folder | Keep the topic's source/output folders. Never put runtime assets here. |
| Runtime asset | established `game/` path | Docs never own runtime art. |
| Generator or recipe | `tools/` | A hardcoded path must exist or point to local-only `archive/`. |
| Local-only reference | `archive/` | Gitignored; never a runtime dependency. |

## Rules

- One topic, one folder. Subfolders exist only when they hold real files.
- One canonical entry per topic. Existing `README.md` files that are the guide itself stay; do not add index-only READMEs per folder.
- One fact, one file. Link to the owner instead of copying numbers or rules.
- Every document must be reachable from this index. An unlinked document is unfinished work.
- Plans stay in `plan/`; game reference stays in `reference/wiki/`; runtime assets stay in `game/`.
- Lowercase-hyphen filenames. Do not mix `pixel-type`, `Pixel Type` and `pixel` for the same concept.
