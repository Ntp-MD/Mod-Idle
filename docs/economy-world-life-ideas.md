# ModWorld — แผนเศรษฐกิจและชีวิตในโลก (งานที่เหลือ + handoff)

สถานะ 2026-10-22: Phase A (วัดฐาน), Phase B (ledger prototype) และ Phase C (ledger สด + เส้นทางขายของผู้เล่น) ถูกใช้งานจริงแล้วในโค้ด รายละเอียดที่ทำแล้วตัดออกจากเอกสารนี้ เหลือเฉพาะงานที่ยังไม่ทำ กฎที่ล็อกแล้ว และพินัยกรรมสำหรับงานต่อ ตัวเลขที่เล่นได้จริงทั้งหมดยังไม่ล็อกจนกว่าจะมี playtest

## งานที่ยังไม่ทำ

### Phase D — ชีวิตหนึ่งเรื่อง (ล็อกรูปไว้แล้ว ตามนี้ตอน implement)

- ขอบเขต: บ้านหลักมุมแรก + เรื่องช่างที่ highspire + โครงการที่กินของจากสายสินค้า ledger เดิม (timber/แร่/อาหารดิบ) ไม่แตะ Black Market, Delivery, Standing; “ตลาดชุมชน” เลื่อนไป Phase E
- บ้าน: ข้อมูลเริ่มที่ `tools/data/town.json → home` สถานะของผู้เล่นอยู่ใน `GameState.home` แยกจาก Standing; บ้านไม่ผูก stash ไม่ให้ส่วนลดสะสมจากการย้าย ไม่เพิ่มค่าพลัง ไม่เสื่อม ไม่มีกิจวัตร; ย้ายบ้านไม่ให้ความสำเร็จที่ทำไว้หาย
- เรื่องช่าง: ลำดับ 4 ขั้น (ช่วยหาเครื่องมือ → เลือกส่งวัตถุดิบหรือช่วยสำรวจแหล่งใหม่ → ร้านและสิ่งที่ช่างทำได้เปลี่ยน → บทสนทนา/งานต่อเนื่อง/ของจัดแสดงที่อ้างสิ่งที่เลือก) ขั้นที่ผ่านแล้วเท่านั้นเปิดขั้นถัดไป ทางเลือกที่บันทึกไปแล้วคงอยู่ตลอดไป รางวัลเป็นเรื่องเล่าและการเปลี่ยนสถานที่ ไม่ใช่โบนัสประสิทธิภาพ; ข้อมูลอยู่ที่ `town.json → stories` สถานะที่ `GameState.stories`
- โครงการ: `tools/data/town.json → economy.projects[ ]` รูป id + ของชุดเป็นหน่วยตามชื่อ trade good ไม่มี deadline จบครั้งเดียว การส่งของหักจากสัมภาระจริงผ่านธุรกรรมเอนจินเส้นเดียวกับการขาย ของหนึ่งหน่วยจบที่ปลายทางเดียว — ห้ามรับทั้งเงินขายและเครดิตโครงการซ้ำ ทองผู้เล่นไม่ถูกสร้างจากการส่งของช่วย
- ผลโครงการใน engine: จบโครงการ “ปรับปรุงเส้นทาง” ต้องบันทึกเครื่องหมายไว้ในสถานะเศรษฐกิจแล้วคูณอัตรา `per_step` ของโอนระหว่างเมืองผ่าน engine (เพราะเป็นผลรายได้ที่แตกต่างจาก config ต้องลงบัญชีเดิม) ไม่แตะสูตรราคาหรือเหตุการณ์; โครงการ “จุดพักระหว่างทาง” ให้ผลเรื่องเล่าและจุดตั้งแคมป์เดิมเท่านั้น ไม่มีตัวเลขรายได้ในช่วง D
- สถานะเศรษฐกิจ: ความคืบหน้า projects และร่องรอยเรื่องให้แนบกับ `GameEconomy` (เซฟก้อนเดียวกับ ledger) หรือเก็บแยกถ้าใหญ่เกิน — ตัดสินตอน implement; เซฟ v21 ต้อง migration ให้ค่าเริ่มว่างสำหรับเซฟเก่าและปฏิเสธชุดที่ผิดรูปโดยตั้งชื่อฟิลด์ตาม pattern ของ v20
- ลำดับเขียนสถานะต่อธุรกรรม (ล็อก): ตรวจของตัวจริงก่อน → หักของ → นับความคืบหน้า/บันทึก one-time → ใช้ผลเมื่อจบครั้งแรก → write-back รอบเดียวจบธุรกรรม
- เกณฑ์ทดสอบช่วง D: ส่งซ้ำ ย้ายบ้าน และโหลดซ้ำไม่ให้รางวัลหรือพื้นที่เก็บของเพิ่ม สถานะเรื่องไม่เดินถอยหลัง โครงการที่เพิ่มผลผลิตไม่ทำบัญชีราคาพัง เกมยังจบได้โดยไม่ทำชีวิตเมือง UI ไม่มีสูตรซ้ำและไม่บังคับให้ทุกคนต้องแต่งบ้าน

### Phase E — ยังไม่เริ่ม (ตัดสินจากผลทดลองของ C/D)

- ขยายเมือง สินค้า เรื่อง และโครงการ “ตลาดชุมชน” เข้าเมื่อมีเหตุผลการเล่นจาก playtest เท่านั้น จำนวนของต้นแบบเป็นขอบเขตทดลองไม่ใช่โควตาเนื้อหา ห้ามให้ภาระติดตามโตตามจำนวนระบบ ถ้าพบว่าจำเป็นต้องเพิ่มระบบที่ตัดออก ให้กลับมาลดแบบจำลองและรายงานหลักฐานก่อน

### พิสูจน์สมดุล (ยังไม่ทำ — ห้ามอ้างสมดุลหรือสนุกก่อน)

- ข้อมูลที่ต้องเก็บจากการเล่นจริง: ทองสร้าง/นำออก/โอน แยกจากของผลิต/ใช้/โอน; รายได้สุทธิต่อเวลาจำลองของแต่ละวิธี (ขายใกล้ตัว เดินขาย วาร์ป แปรรูป) รวมต้นทุน; ผู้เล่นอธิบายการเลือกปลายทางได้ไหม; ภาระเฝ้าตลาดหรือกดงานย่อยเพิ่มขึ้นหรือไม่; ผู้เล่นกลับตัวได้เมื่อเงินหมดหรือโครงการค้าง; เหตุการณ์จำกัดเวลาเปลี่ยนแผนผู้เล่นเพราะอะไร; ผู้เล่นกลับบ้าน/ช่วยเรื่องเพราะอยากเห็นผล ไม่ใช่เพราะโบนัสสะสม
- ความถูกต้องช่วง D ที่ต้องเพิ่มเป็นเทสต์: รายการในเกณฑ์ทดสอบช่วง D ด้านบน
- เกณฑ์เดิมคงใช้: บัญชีและธุรกรรมตรวจด้วย gate ได้ แต่ราคา กำไร จังหวะเล่น และจำนวนเนื้อหาต้องประเมินจากข้อมูล ไม่ใช้ gate บังคับตัวเลขที่เดาไว้

### การตัดสินใจที่ยังค้างของเจ้าของ (ห้ามตัดสินแทน)

- **ตัวคูณเงินตรา ×100** (ledger row 6) — ถ้ายอมรับ ทองใน `capacity_gold` งบเมือง แหล่งทอง และราคาทั้งชุดต้องปรับตามตัวคูณเดียวกันในการเปิดใช้ ไม่ใช่ผสมเลขคนละสเกล
- **ชุดเกริ่ม opening.gear** (ledger row 11) — ขอบเขตเริ่มเกมยังเปิด

## กฎที่ล็อกแล้ว (ห้ามทลาย มีเทสต์กันอยู่)

- การเปิดตลาดหรือขอราคาเป็นการอ่าน ไม่เดินเวลา ไม่เติมงบ ไม่โตของ ไม่เปิดเมืองหรือ Waypoint
- หน่วย: stock รายสินค้า, capacity ต่อหมวด, งบเป็นทอง — ตามข้อมูลปัจจุบันใน `economy`
- ลำดับ step: activate events → produce → consume → transfer (คำนวณจากสภาพต้นช่วง; สินค้าเดียวไม่ผ่านหลายเมืองในรอบเดียว) → เติมงบ → advance
- ธุรกรรมขาย: ของหนึ่งหน่วยปลายทางเดียว; Haggling ใช้ครั้งเดียวต่อธุรกรรม; เครดิตเศษเงินใช้เส้นทางคำนวณร่วม ไม่กินกำไรจากการปัดเศษ
- ออฟไลน์: ห้ามลัดเวลาเพื่อคำนวณง่าย; catch-up ออนไลน์/ออฟไลน์ต้องได้สถานะเดียวกัน เหตุการณ์เดินรวมออฟไลน์; ถ้ามีการสุ่ม ใช้ seed ที่บันทึกแยกจาก combat/loot
- Delivery เดิมคงรางวัล กฎหมดอายุ และการจ่ายบางส่วน ห้ามย้ายภาระรางวัลเก่าเข้า treasury ช่วง D
- การเพิ่มสถานะใหม่ทุกครั้งต้องมี migration + round-trip + ปฏิเสธชุดผิดรูป (ตามชื่อฟิลด์) และ reject เซฟเวอร์ชันที่ไม่รู้จัก
