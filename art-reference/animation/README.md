# Animation atlas art reference kit

เริ่มอ่านไฟล์นี้ก่อนส่งงานให้ agent เจนภาพแอนิเมชัน (character/monster sprite
atlas) โฟลเดอร์นี้เป็นแม่แบบอ้างอิงชุดเดียวสำหรับมุมกล้อง 3/4 top-down, โครงสร้าง
กริด atlas, การเรียงทิศทาง 8 ทิศ, และ clip phases มุมกล้องมาจากโค้ดจริง ไม่ใช่การเดา
จาก screenshot

ภาพที่ generate ทุกไฟล์เก็บไว้ใต้ `outputs/` เพื่อรอ approve ก่อนนำไปใช้จริง
ห้ามคัดลอกเข้า `game/public/` หรืออ้างในโค้ดจนกว่าจะอนุมัติ

## เริ่มใช้งาน

1. อ่าน [base-prompt.md](base-prompt.md) — เป็นเทมเพลตเดียวสำหรับงาน atlas แอนิเมชัน
2. เลือกชุด pose ที่ต้องการ: locomotion (idle/walk/turn), action
   (windup/release/recovery), outcome (hit/death) ตาม `docs/animation.md`
3. กำหนดกริดและขนาดเซลล์ตามเป้าหมาย (ดูตัวอย่าง `art-reference/monsters/beast/harpy/animation/meta.json`)
4. ใช้ด่านตรวจด้านล่าง แล้วลองวางในเกมก่อนทำชุดถัดไป

## สัญญากล้อง (จาก `game/src/presentation/arena-camera.ts`)

**มุมอธิบายโดยประมาณ: 3/4 top-down, effective elevation 45.92°** — ค่านี้อนุมานจาก
ellipse ratio ของเมทริกซ์; renderer เก็บ affine matrix ไม่ได้เก็บมุมกล้อง 3D แยกต่างหาก

| ค่า                         | ตัวเลข                                         |
| --------------------------- | ---------------------------------------------- |
| Effective elevation         | 45.92° (3/4 top-down ~45–55°)                  |
| เมทริกซ์ฉาย M               | [[137.5274, 32.7446], [−26.1957, 98.2339]]     |
| การบีบฐานตามแกนหลัก        | minor/major = 0.7183; ความยาวแกนโลก Y/X หลังฉาย = 0.7396 |
| วงรีเท้าแตะพื้น             | minor/major = 0.7183; แกนเอกบนจอ −2.29°, ทิศแกนเอกในโลก 11.75° |
| 8 ทิศ                       | S SE E NE N NW W SW (ตามเข็ม, ใต้ก่อน)         |
| จุดศูนย์กลาง sector (world) | 14.93°, 68.20°, 103.39°, 319.64° (ไม่สม่ำเสมอ) |

**จุดต่างจาก skill VFX:** ตัวละครเป็น **upright sprite** — ตัวยืนตรง เห็นหัว/ไหล่
จากด้านบน มีเพียงฐาน/เท้าที่แตะระนาบพื้นและผิดรูปตาม projection ไม่ใช่ footprint
ทั้งตัวแบบสกิล

หมายเหตุพิกัด: 11.75° คือทิศแกนเอกในพิกัดโลก (จาก MᵀM) ไม่ใช่มุมวงรีบนจอ
มุมแกนเอกบนจอคือ −2.29° (จาก MMᵀ) ทั้งสองค่ามาจากเมทริกซ์เดียวกัน

ใช้ direction labels (`S`, `SE`, `E`, `NE`, `N`, `NW`, `W`, `SW`) เป็นชื่อท่า
เท่านั้น อย่าแปลงเป็นมุมโลกจาก turntable candidate: manifest นั้นระบุว่า requested
bearings ยังไม่ได้รับรอง Runtime รับ facing เป็น radians จาก +X แล้วแปลงผ่าน
`arenaFacingIndex` ให้เป็น screen-facing sector

## มาตรฐานทิศทาง: 8 ทิศ

งาน source set ใหม่ทุกชุดใช้ **8 ทิศ** (`S SE E NE N NW W SW`) — 4 ทิศแข็งที่มุมทแยง,
16 ทิศเพิ่มต้นทุนอาร์ต 2 เท่า (272 slots เทียบกับ 136) แต่ผลที่เห็นในเกมไม่คุ้ม
เมื่อสไปรต์แสดงผลเล็ก 8 ทิศคือจุดสมดุลสำหรับมุมมอง 3/4 นี้

- สัญญา poses ต่อ species คือ **136 slots**: idle 1×8 ทิศ, walk/attack/hit/death
  4×8 ทิศ — เป้าที่ `tools/monster-animation-v5-inventory.py` (`TARGET_DIRECTIONS`) ใช้ตรวจ
- Runtime แปลง facing เป็น 8 screen-facing sectors เท่านั้น ไม่มีช่องให้ทิศที่ 9–16
- ชีต 16 ทิศ (เช่น `outputs/giant-idle-16-direction-contact-sheet-v1`) เป็น visual draft
  สำหรับดู concept ไม่นับเป็น source coverage ห้าม promote เข้าเกม

## Clip phases (จาก `game/src/ui/combat/animation/manifest.ts`)

- **locomotion**: `idle`, `walk`, `turn`
- **action**: `windup`, `release`, `recovery`
- **outcome**: `hit`, `death`
- เพิ่มเติม: `channel`, `despawn`

## ข้อควรระวัง

- **มุมมองของตัวละคร ≠ การบีบพื้น** ตัวละคร upright ยืนตรง มุมกล้องเห็นหัว/ไหล่
  เท่านั้น การบีบ 0.718 ใช้กับฐาน/เท้าที่แตะพื้น ไม่ใช่ทั้งตัว
- **ทิศทางต้องเป็น silhouette ที่ต่างกันจริง** ไม่ใช่การหมุน/สะท้อนภาพเดียว
- **จุดยึดเท้าต้องอยู่ y = 0** (เมตร) และแนวสัมผัสพื้นคงที่ตลอดทุกเฟรม ตาม
  `docs/animation.md`
- ตาม [../map/README.md](../map/README.md) อย่ากำหนดองศาจาก screenshot หรือ
  คัดลอกค่าด้วยมือ ใช้ค่าที่ refresh จากโค้ดจริงเท่านั้น

ดู [../map/calibration/README.md](../map/calibration/README.md) เพื่อแยกมุมกล้อง
ที่ใช้สร้างงานออกจากหลักฐานการวางแนวในเกม

## ด่านตรวจ animation art ก่อนเข้าเกม

เก็บภาพทุกชุดไว้ใน `outputs/` และคงสถานะ `draft-review` จนกว่าจะผ่านทั้งตัวตรวจเชิงตัวเลข
และการดูใน runtime จริง

### 1. ตรวจรูปทรงและ atlas อัตโนมัติ

สำหรับ atlas มาตรฐาน 8×5 ให้สร้าง pose เป็น PNG แยกทีละภาพ แล้วใช้
`tools/monster-animation-compose.py` จัดกริดและจัดระยะโปร่งใสด้วยโค้ด วิธีนี้ไม่ต้องพึ่ง
image model ให้สร้างเส้นแบ่งเซลล์เอง ตัว compose จะหยุดเมื่อ pose ขาด ถูกครอป มีหลายตัวในภาพ
หรือจัดลง runtime cell ไม่ได้ และเรียก atlas QA ก่อนส่งผลลัพธ์ออกมา

สำหรับ atlas ที่จัดกริดมาแล้ว ให้รัน
`python -B tools/monster-animation-qa.py --metadata <candidate-meta.json>`
ก่อนตรวจด้วยตา QA ปัจจุบันเช็กจำนวน/ตำแหน่งเฟรม ขอบเซลล์ alpha padding การครอป เฟรมซ้ำ
และ drift ของแนวพื้น อย่าถือว่า `PASS` นี้แปลว่าขนาดลำตัวถูกต้องแล้ว

### 2. ตรวจสเกลโดยไม่เหมารวมความเปลี่ยนแปลงของท่า

ดู contact sheet สองแบบของทุกเฟรม:

- ภาพสีจริงในกริด เพื่อเช็กทิศ อาวุธ รูปร่าง และจังหวะของท่า
- silhouette สีเดียวที่วาง feet/root ไว้บนเส้นเดียวกัน เพื่อให้เห็นตัวที่หด ขยาย ลอย
  หรือกว้าง/สูงผิดจังหวะได้ชัด

เทียบขนาด torso/head/core กับเฟรมอ้างอิงของคลิป แยกอาวุธ โล่ ปลายหาง ปีก และระยะฟาดออกจาก
ขนาดลำตัว การกางปีก ยกดาบ หมอบ ล้ม และ dissolve เปลี่ยนขอบนอกได้ แต่ไม่ควรทำให้ทั้งตัว
เปลี่ยนสเกลโดยไม่ตั้งใจ ถ้าท่าต้องเปลี่ยนสเกลจริง ให้ระบุเฟรมและเหตุผลไว้ใน metadata
แทนการปล่อยให้ runtime เดาจากกรอบ alpha ของเฟรม

แผนต่อไปคือเพิ่มรายงาน per-frame สำหรับ alpha bounds, พื้นที่ silhouette และ root/foot line
เข้า `tools/monster-animation-qa.py` ให้รายงานการเปลี่ยนเกินช่วงที่คาดเพื่อส่ง review
แทนการ fail จากขอบ silhouette อย่างเดียว เพราะท่าโจมตีและรูปร่างของแต่ละชนิดเปลี่ยนขอบได้
อย่างตั้งใจ ตัวตรวจนี้ต้องครอบทั้ง player และ monster และแยกข้อยกเว้นของ death/floating
หรือ clip ที่ตั้งใจเปลี่ยนสเกลไว้อย่างชัดเจน

### 3. ตรวจในเกมก่อน promote

เปิด clip ใน showcase ที่ขนาดจริง 1920×1080 แล้วดูทุกเฟรมของ idle, walk, attack, hit และ death
ในทิศที่ runtime ใช้ ตรวจแนวเท้า/ราก ตัวลำตัวแยกจากอาวุธ ตำแหน่ง contact ของการโจมตี
และดูว่าการเปลี่ยนเฟรมไม่มีทั้งการกระโดดของ anchor หรือการ scale ทั้งตัว

จะ promote เข้า `game/public/` และ runtime registry ได้เมื่อผ่าน geometry QA และ visual review
ครบทั้งสองอย่าง หากจำเป็นต้องมี squash/stretch ให้เป็นข้อมูล animation ที่ระบุเจตนาและจำกัดอยู่
ในคลิปนั้น ห้ามสร้างจากการคำนวณ scale ด้วยความสูงกรอบ alpha ต่อเฟรม
